## 專案定位
- `SinoPac Auto Trading / 永豐自動交易` 是下游自動交易執行框架。
- `private_model_vault` / `private_signal_source` 是上游訊號來源；永豐自動交易不反推 private upstream universe。
- 公開框架不能包含 private upstream selection rules、API key、secret、CA 憑證、真實券商帳密與私有交易紀錄。

## 目前生效中的選股來源規則
- 永豐自動交易目前固定從 `<WORKSPACE>\data\private_preselect_export\*.json` 找 上游預選來源。
- 正式買進來源必須以 `target_trade_date` / `source_target_trade_date` 對準目標交易日。
- 執行層只使用 JSON 內的 `a_preselect`，也就是 上游預選。
- `b_preselect` 不可進入 preselect、final_list、sizing 或 order。
- A/B 重疊股票只有因為它也在 A 裡才可保留，不因 B 額外加權。
- 若找不到 target 對準目標交易日的 上游預選，執行層直接 pass，不允許回退不相關舊日期名單。

## 10:00 上游預選確定規則
- 永豐自動交易的「確定 上游預選 / materialization」固定在目標交易日 `10:00 Asia/Taipei` 之後才允許執行。
- 操作提醒固定句：`10點後才會執行永豐自動交易的確定上游預選工作。`
- `prepare_week`、`track_until_final`、`finalize`、`refresh_dashboard` 在 10:00 前不可把 上游預選確定成當天買進籃子。
- `buy_loop` 不能只因為 `sizing.csv` 存在就買；這份 sizing 必須是 10:00 後 `finalize` 出來，且預算 / hard budget / week id 都符合授權。
- 2026-W18 目前授權設定：`weekly_budget=60000`、`hard_budget=60000`、`overrun_tolerance=0`、`weekly_execution_enabled=true`。

## 買進與追買規則
- `buy_loop` 只在本週第一交易日開新整包買單。
- 目前 `allow_buy_after_first_trade_day=false`，所以週二/週三不會吃新的 上游預選買進。
- 如果未來明確打開追買，追買也只追第一交易日那包沒買到的剩餘股數：
  - 讀第一交易日的 `sizing.csv`
  - 沿用第一交易日的 `strategy_lot_id`
  - 扣掉本週已買數量
  - 只補未買到的剩餘量
  - 不吃追買日新產出的 上游預選

## live 買進失敗後的修復與續下規則
- 這套規則適用所有未來整包 live 買進，不只 2026-04-27。
- `buy_loop --live` 若被 live gate 擋住、broker 回 failed/rejected/error、單列 blocked、或目標股數沒有完整送出，會寫入 `repair_confirmation_required`。
- 修復 blocking issue 後不能直接續下；要先跑 `repair_confirmation --live`，產生 broker/local 對帳報告。
- 報告必須列出：
  - 買了什麼 / 已成交
  - 已送但未完全成交
  - 什麼還沒買 / 尚未送出
- 報告要寄給使用者，後續依使用者 mail 回覆的具體內容判斷，不要求固定制式句。
- 只有回信內容明確授權補下全部剩餘單、或明確指定可補哪些尚未送出的股票時，才可補下符合範圍的剩餘單。
- 若回信不同意、要求先停、內容不清楚、範圍對不上報告、或要求補已成交/已送等待成交/狀態不明項目，就停止並回報。
- 防重買是最高優先順序；同一 `strategy_lot_id` 若在本地 `orders.csv`、`positions.csv`、week lot ledger、broker fills、broker order id、或 broker `custom_field` 已有 active / filled buy，就不得再送。
- 程式本體目前有 `repair_confirmation_required` 與 `repair_confirmation` report；Gmail thread 查詢與依回信內容續下目前由 Codex/自動化流程執行，尚未做成本體硬 gate。

## 賣出規則
- 賣出只處理策略持倉，不處理券商帳上 excluded positions。
- `sell_loop --prepare-only --live --confirm-live` 可在開盤後先做只讀準備，不送賣單。
- 真正 `sell_loop --live --confirm-live` 只在本週最後交易日、賣出時間窗與所有 live gate 通過時才可能送單。
- 整包保守淨利必須大於 `max(總成本 * 0.8%, 3000 TWD)`，且保守淨利已扣賣出手續費與證交稅。
- 整包低於門檻、0、或虧損，一律 hold。
- 一旦整包達標，策略持倉整包送賣；單股門檻與虧損股拖累比例只作觀察欄位。
