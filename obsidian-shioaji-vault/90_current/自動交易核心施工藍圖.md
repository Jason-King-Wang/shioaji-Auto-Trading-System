## 終極資料鏈
- `上游預選 JSON -> prepare_week -> finalize/sizing -> buy_loop -> broker -> fills -> strategy positions -> realized/unrealized pnl -> sell_loop -> report/Obsidian`
- 目標不是只會送單，而是整條鏈都能回寫、驗證、結算、解釋，且能在失敗後安全修復。

## 已確認的賣出邏輯
- 賣出只處理策略持倉，不賣券商帳上其他 excluded position。
- `sell_loop --prepare-only` 可在開盤後先做只讀準備；真正賣單只有本週最後交易日才可送。
- 單股會計算保守出場價：
  - 13:20 前：`bid1/last_price` anchor 下修 2 tick 或 0.35%，取更保守者。
  - 13:20 後：下修 3 tick 或 0.5%，取更保守者。
- 整包保守淨利必須大於 `max(總成本 * 0.8%, 3000 TWD)`。
- 整包保守淨利已扣賣出手續費與證交稅；負數、0、或低於門檻一律 hold。
- 一旦整包給 `recommend_exit`，策略持倉整包送賣；單股門檻只做觀察欄位，不阻擋整包賣出。
- 虧損股拖累 / 獲利股貢獻比例只保留為觀察欄位，不是獨立阻擋條件。
- 真實送賣單前仍需通過 live gate、broker signed、市場開盤、13:00 後、quote 新鮮、無 ambiguous fill、無 excluded position scope 衝突、無 broker 持股小於策略持倉矛盾。

## 為什麼 上游預選要等 10:00
- 週一早上 06:00 才開始執行預選名單的產出，09:00 開盤附近不保證最新 上游預選已經產完。
- 我們很可能在週一開盤前做永豐自動交易測試；若 10:00 前允許 `prepare_week` / `finalize`，可能把週末已存在的 上游預選檔誤鎖成週一正式買進名單。
- 因此永豐自動交易不是看到檔案就確定 上游預選，而是等目標交易日 10:00 後，再讀 `target_trade_date` 對得上的 上游預選來源並重新 `finalize`。
